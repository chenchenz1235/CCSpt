# 研发管理：项目日报

## 入口与必填

进入自己的 OA：研发管理 → 项目日报，优先复用已打开编辑页。不要照搬别人的模板 ID、菜单 ID、记录 ID。
标题一般是主页面 `#subject`；正文 `zwIframe`，CAP4 页面 `type=create`，查看时 `type=browse`。
日期常用 `#field0002_format`，日报类型 `#field0018_inner`。与用户指定日期核对，不把示例日期写入正式表单。
今日工作与明日计划均需补齐。未给明日计划时询问，不自行编造。是否要求下周计划以实际规则为准。

## 项目选择

优先读取本机 .state/recent-projects.json 中用户已确认的项目映射；公开包不包含真实项目号。
没有映射时查询正式项目名。多个合理候选必须列出编号、名称、版本请用户选择，确认后才写入。新版本不得套用旧编号。

今日工作信息不是普通输入框：
1. 在目标行点 `[id^="field0012_"] .cap4-text__relation`。
2. 菜单 `li.selectForm-list__item` 中选精确文本“今日工作信息”。“选择衍生项目”是另一数据集。
3. 主页面出现 `iframe[name^="layui-layer-iframe"]`，等待 Frame URL 包含 `type=relation` 且搜索框可用。
4. placeholder“搜索关键字”的第0个输入按编号筛选，第1个按项目名；点精确按钮“筛选”，等预期行出现。
5. 从精确编号文本向上定位 ancestor::tr，只选择该行的 checkbox，再点主页面“确定”。
6. 回到 zwIframe 等正式项目名出现，核对开发号。

## 已验证字段模式

动态 record ID 每次不同，按前缀和所在行定位。
今日行：`tr[data-record-id]` 中包含 `[id^="field0012_"]` 的行。

| 字段 | 行内选择器 |
|---|---|
| 开发号 | `[id^="field0025_"] input` |
| 工作项目 | `[id^="field0012_"] .is-relatinbrowse`，通过关联列表选 |
| 描述 | `[id^="field0007_"] textarea` 第0个 |
| 小时 | `[id^="field0006_"] input.is-activeInput` |

小时控件还有只读显示输入，写入可编辑的 is-activeInput 后 Tab/blur，读回核对。
textarea 有 opacity:0 的测量副本，填第0个或明确排除透明副本。
“插入行”的三个区域：nth(0) 今日，nth(1) 明日，nth(2) 下周。新增后等新字段出现再填写。

明日行包含 `[id^="field0008_"]`，工作信息是该节点内 input，描述是 `[id^="field0014_"] textarea` 第0个。
明日项目名是可直接输入的普通文本；沿用用户已确认项目。没有工时字段，不额外填小时。
其他 OA 版本字段可能不同，先对照真实页面，不机械照搬。

## 文风、预览和发送

工作内容按主要事实简洁润色，可写动作、结果和剩余事项，不创造未提供的完成情况。
核对日期、项目号/版本、描述、每项小时及总工时、明日计划；本机保存实际 DOM 值预览，给用户看后等待“发送吧”等明确确认。
用户确认后只点一次主页面 `#sendId_a`。先记标题、编辑记录 ID、日期、项目和工时，查看必填或确认弹窗，不盲目重复点击。
成功依据：已发详情 URL 的 method=summary、openFrom=listSent，详情 summaryId 与原编辑 ID 对应，且持久化项目、描述、工时和明日计划一致。
已发送不等于流程已审批结束。下次发新日报时不能使用旧 affairId/summaryId。
