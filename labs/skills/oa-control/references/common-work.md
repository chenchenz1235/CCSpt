# 通用查询与流程排查

## 连接

读取 config.local.json 中的 OA URL；用 `import {chromium} from 'playwright-core'` 和 `chromium.connectOverCDP(config.cdpEndpoint)`。
复用现有页面，按已观察到的 URL/标题定位；重连后不要依赖标签序号。结束脚本时 browser.close() 断开客户端，不关闭用户的 Edge 窗口。
选择器和业务控件需随实际 OA 版本核对。

## 列表

协同工作 → 待发事项 / 已发事项。主窗口列表通常位于 `mainIframe`。
待发 URL 参数 `method=listWaitSend`，已发 `method=listSent`；等 Frame URL 及目标行出现再读取。
`node scripts/oa.mjs query waiting` 读取待发，`query sent 关键字` 按标题筛选已发，结果保存在本机 `.state/last-query.json`。
只采集当前结果页，检查总条数与分页；没有命中时筛选等待可能超时，不能把旧列表当作新查询结果。

## 单据与流程

待发包含草稿、撤销、被回退；这与“审批人未处理”不同。先找对列表，再看处理人意见和当前节点。
点击标题可能产生新页，点击时等待 popup，再等待正文 Frame 完成加载。iframe 元素先出现时 URL 可能仍是 about:blank。
正文常在 zwIframe，编辑值需 inputValue；只读详情用 innerText。
“当前表单为测试表单”等提示按实际情况说明，不能把点击发送或编辑成功当成正式业务成功。

## 删除与清理

仅按用户明确要求核对目标编号、标题和选择框标识，不选中其他单据。
已验证有些致远 OA 的待发列表可以直接删除草稿/撤销单：选择行 → 删除 → 不可恢复确认 → 删除成功 → 确定 → 刷新核对目标消失。
先观察系统实际行为，不因为某次经历而默认所有表单都必须“先发出再撤回”。删除没有意见栏时，不能宣称本地备注已写入 OA。
发送、审批、撤回、删除分别是不同操作，按用户当次范围执行。

## 观察和提交失败

截图超时不代表已保存的文字或之前的业务操作失败，先检查页面与结果。
记录发送前预览与业务 ID；只点击一次，结果不明先查已发，不盲目重试。
业务详情及截图只保存在本机 .state，不加入公开仓库。
