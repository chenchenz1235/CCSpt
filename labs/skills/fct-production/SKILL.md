# 产线FCT工装编制

适用于产品基本功能正常，但FCT代码可能未更新或不正确的控制板、电机驱动板。方案用于指导软件完善FCT；不能让旧FCT遗漏限制检测范围。默认中文，沿用用户最新认可的模板和协议框架。

## 使用路径：三个主步骤，软件审核可选

按用户当前阶段接续，不强制从头重做。已有确认直接沿用；需要确认的是检测项目和方案中的工程决策，不是每次保存文件。用户只要求修订文件时，完成授权修订，不重新启动所有关卡。

### 第一步：项目总览与检测项目确认

读取原理图、可用PCB及正常业务代码，按实际电路提取候选项目，输出一张信息密度高的表：**类别｜本项目实际配置｜拟测试方法｜其他**。按 [项目总览](references/project-start.md) 执行。

展示实际芯片数量/职责、对外接口、板上电源、AD采集、输出和负载，以及拟采用的检测方式。方法简述如“工装集中检测”“采样协议对比”“静态温度对比”。本阶段不加“接口/采集归属”列，不铺MCU引脚、报文和详细针点。项目从功能与信号路径提取，不能套固定必测表或只抄FCT结构体；分类只用于反查遗漏。

对外通信口优先作为主测试口；本用户常见2×5端子通常内部使用，应按本板核实。其他选择通信收发法的待测外置口拟通过进入FCT收发验证；电流环可仅做固定高低状态与真实RX回传，不强制报文验证，详见检测方法。内部芯片间通信不单列展示或测试，利用已有通信保护故障码判断。FG配置写产品实际功能及开漏/推挽结构，拟测试方法再写FCT固定脉冲，不把产测模式写成产品常态。

交使用者增删确认。确认后进入第二步，不输出整套正式资料。

### 第二步：规划测试方案并确认软件配合

直接在聊天框输出 **阶段｜推荐检测方案｜软件对比后的待确认建议**，按 [方案规划](references/test-plan.md) 执行。基本顺序：供电等待3～5s、通信和版本 → 工装激励及静态检测 → 输出组1/组2（确需时组3）→ 拖动 → 必要且已确认的故障检测 → 结束。

根据第一步对象安排阶段；LED属于输出组，一般稳定点亮后测一次压降。软件对比区分“当前协议架构支持”和“不支持”，随后列具体确认事项。已有架构内调整传输内容、结构体成员、输出形式或执行逻辑属于支持，但必须标明当前实现需改；新增协议能力才列为不支持。所需转发请求、回复及停止路径必须核实。

本步的代码阅读只为判断方案和协议能力，不等于开展完整软件审核。把差异和建议交使用者确认，确认前不定新的协议功能或直接输出最终方案。用户可接受软件修改，也可要求调整测法。

### 第三步：输出正式资料和软件修改指导

按已确认方案实际生成并交付：**测试点表、测试流程、通信协议、软件修改指导及检查表**。不能只给对比报告或聊天摘要。按 [测点、表格及协议](references/points-tables-protocol.md) 落实。

测试点表面向工装工程人员，仅列实际需要扎针的点；不扎针的项目及端子接线写入流程或接线配置，流程完整覆盖全部已确认测项。测试点和流程必须在现有模板中更新，保留列结构、合并、字体、边框和打印设置，必要时增加行并调整行高。流程允许加入阶段文字和浅色分块，不借机重新设计。测试范围统一“理论：…；范围：…”，按该参考中的用户默认容差及项目覆盖规则填写。协议沿用最新认可版本。

指导文档独立列目标结构体成员/来源/单位/缩放、输出组1/2各输出、进入FCT、跨芯片转发与回复、拖动计时和停止、注意事项。各项附验收条件、检查结果/证据空栏，供软件修改后检查；文件编制完成不表示软件已修改或已通过。操作流程只写执行内容，推理及软件差异放指导文档。

### 可选：软件修改后的审核

仅在用户选择或明确要求时，按 [实现核对](references/code-check.md) 对照已确认资料检查新代码。默认提出问题和修改建议，不自动改固件。单独记录静态核对、编译和实机证据；无台架证据不称测试通过。未选择审核不妨碍第三步交付。

## 输入与复用资料

测试方法按需读 [检测方法](references/test-methods.md)，不要一次加载全部历史案例。历史案例由项目方另行提供，其中位号、参数和旧待确认值不是通用规则。成熟案例先依据原始资料形成经确认的实际输出，再和参考答案比较；已读答案时如实说明。

## 保留的工程原则

- 检测方式按最终判据区分测量、协议对比、测量＋协议对比、通信收发验证；发控制命令后由工装测电压仍为测量。
- 多个选择通信收发法的待测外置口依次重复进入FCT并确认（仅做高低状态检测的电流环不在此列），随后固定主外置口完成后续测试。主口所需功能确实无法支持时，才讨论保留其他口承担必要动作；驱动进入缺失不等于拖动不支持。转发链路两端都查，地址和报文不得照搬案例。
- 产线仅支持单面扎针，默认统一在PCB背面选裸露金色测试点；中心距≥2.5mm，推荐直径1.5mm，最小1.2mm且不能全部采用1.2mm。没有硬件规划的测试点时，可选同一扎针面的端子焊盘，工装使用梅花针，所选针点中心距仍须≥2.5mm。主要供电可用端子连接；专用测试点和端子焊盘均无合格背面点时列硬件整改需求，不混用正反面针点。具体核实要求见测点参考。
- 供电与测量分别写清相对主供电的隔离/非隔离关系、参考端及共地限制，不以“隔离测量”代替供电隔离说明。5V检测范围为4.8～5.2V（±0.2V）。
- 针板一次压合全部配置测点，按状态集中列出可同时检测的信号。通信动作使用协议指令名称。FG测试固定脉冲，不用真实转速判定；拖动也不要求实际旋转。
- 电流理论零点优先查matlab_variable.c的current_zero_ad_offset及各通道等效参数，再核对电路与实际通道；电机、PFC、PV分别判断。软件保护偏差不直接当工装判限。检测用停止/PWM关闭等适用条件下的真实原始AD；温度、电压可回传物理量，float不决定单位，设定回显不证明通过。
- LED一般一次A-K压降检测，不使用光感。可控LED可在FCT点亮；常亮LED按实际供电测量。
- AC/DC电源继电器保留正常吸合逻辑，只检测状态，不加入强控输出组。驱动电平不能独自证明触点闭合。
- 无硬件锁存器不追加锁存测试；专项故障注入按实际需要确认，不默认增加。电流环按电路的限流、参考地和极性设计固定高低及真实RX回传。
- 负载与电流按板型确认；固定电机0.5A与低压板专用小电感5A都不能作为所有工程的定值。已确认的特例需在资料中说明。

## 完成检查

确认每项有方法、接点或协议字段、有效状态及理论/范围，三份工装资料和软件指导一致。备份最新文件后编辑，渲染核对可读性；被占用时另存明确修订文件，不关闭用户文件。协议字段偏移、数据长度、校验及示例独立复核。最后提供可打开的文件，区分目标方案、代码实现和实测状态。
