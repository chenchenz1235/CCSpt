# 案例输入资料规范

每个案例独立一个文件夹，目录名建议为“项目名_板号_硬件版本”。保留原始工程内部文件名与目录，避免破坏引用。未提供的资料在说明中标注，不必建立空目录。

## 交付目录与格式

|目录|放什么|格式及要求|用于哪个阶段|
|---|---|---|---|
|00_项目说明|板号、硬件/装配/固件版本、目标功能、已知不测项、资料对应关系|TXT或MD；标明每类当前基线文件的准确路径|所有案例|
|01_原理图|完整电路及层次子页|优先原生工程＋可搜索PDF；不要只提供局部截图|方案编制必需|
|02_PCB|布局实体、顶底装配信息|可读取PcbDoc/kicad_pcb等；不是只有PrjPcb；已有坐标表附单位、原点、板面和观察方向|测点定位必需|
|03_BOM与实物|位号、阻值/容值、型号、DNP/选装；板正反面照片|BOM用XLSX/CSV，照片清晰可辨位号和遮挡|用于核对关键器件及扎针条件；缺项注明|
|04_工装与协议基线|沿用的测试点表、流程表、内部协议；工装与负载的已知条件|测试表XLSX、协议DOCX；原模板和当前采用版标明身份；已有设备/接线资料可原样提供|编制输出、继承现有协议和能力|
|05_软件|完整工程及依赖，FCT源/头文件所在位置|保留原目录；注明源码版本、目标型号及已有构建方法；不只交两个FCT文件|第二步软件能力判断需要；修改后全面审核为可选，首轮可缺|
|06_验证记录|工装实测、串口报文、判限依据、已知问题|现有XLSX/CSV/TXT或报告即可；报文标注收发方向及工况|验证是否成熟、收敛判限；没有则写未提供|
|07_参考答案|成熟案例最终使用的测试点表、流程、协议及针点图|保留最终原件；标明实际量产版和验证状态|用于检验Skill，评估时与输入分开|

资料须可在授权环境下读取，硬件版次及装配差异能追溯。无需为了交资料重新手填全部信号、测点或报文字段，这些应由Skill提取。

## 项目说明可直接填写

```text
项目名称／板号：
原理图版本／PCB版本／BOM装配版本：
固件版本或日期／工程路径／FCT源和头文件位置：
本次阶段：第一步项目总览／第二步方案确认／第三步资料输出
是否需要软件修改后审核（可选）：
工装沿用哪个案例或设备：
最新模板与协议基线路径：
特殊要求与明确不测项目：
已验证状态：仅方案／代码核对／样板通过／已量产
验证记录与最终参考答案路径：
缺少资料、已知问题或版本差异：
```

## 用成熟案例检验Skill

案例资料中的“编制前基线”和“最终参考答案”分开。若检验从零编制能力，先根据00～06中编制时可获得的资料输出，再读取07作对照；若检验现有文档修订能力，直接使用最新正式文件。不要为了盲测隐去任务确需继承的协议框架或人为制造版本缺失。

对照关注实际测项取舍、接线/参考端、实采来源、单位判限、报文布局和模板，而不是是否逐字相同。未提供台架证据就不判定为实机通过。
