# 启动资料与项目填写模板

## 1 开始前准备哪些资料

|资料|推荐形式|用途|缺少时怎么推进|
|---|---|---|---|
|项目与版本说明|简短README或文字说明，列板号、硬件版次、装配版本、固件基线|保证原理图、PCB、BOM和实板对应|先列版本待核对，不能用混合版本定加工针点|
|完整原理图|原生工程及全部子页；另附可搜索、可放大的PDF|梳理接口、供电、采样、驱动和参考地|可先用清晰PDF编制；只有截图时仅处理能明确识别的部分|
|PCB布局|可读取的PcbDoc、kicad_pcb等原生文件；配顶底层布局及装配信息|找同网焊盘、板面和实际可接触位置|可先写器件位号及脚号；针床可达性和坐标待落实|
|BOM及装配差异|XLSX/CSV，含位号、数值、型号、DNP/选装状态|核对分压、零点、负载、电源及不同机型差异|不因缺完整BOM停工；缺少的关键型号/阻值单独确认|
|现有工装测试点及流程|用户最新认可的可编辑XLSX；保留原始模板|继承列结构、测量方法、工装已有能力和操作习惯|先整理已确认要求，不照搬旧项目位号和判限|
|内部通信协议|可编辑DOCX及已有报文例子，必要时附串口记录|继承帧结构、指令、校验及解析约定|先明确现有框架，不自行编新指令|
|软件工程|完整可读取工程，含FCT源/头文件、采样、输出执行、状态、通信及参数模块|第二步核对协议能力；另可选修改后审核|首轮可缺；第二步不能只给FCT两个文件并声称链路已核实|
|工装和测试负载信息|已有方案、接线表、仪表型号或能力说明；电机/模拟负载型号|确认电压范围、隔离、测量方式、激励和同时测试数量|从既有方案推导已有能力，未知项标待验证，不要求一次提供完整能力表|
|实物及调试资料|顶底面清晰照片、样板数据、已知故障样本、旧工装记录|确认遮挡、针点可达性、稳定时间和判限|首轮允许缺少，不能把理论值当实测量产限值|

Altium的PrjPcb只是工程索引，不能代替SchDoc/PcbDoc实体文件；KiCad原理图须包含相关层次子页。建议按项目打包，保留原目录与相对路径，附资料清单，不只发若干散图。

只有Gerber时，可辅助核对铜层、阻焊及焊盘，但普通Gerber未必提供可靠的网络对应关系；搭配IPC-D-356网表、测试点清单或CAD导出网络数据更有用。制造文件、网表和实板版本必须一致。装配图或坐标表也不能独自证明焊盘可扎针。

文件需要能在获授权的工具中正常读取。遇到企业加密文件，由资料所有人按公司允许的方式提供可读取副本或导出件；不尝试绕过保护。



## 第一步项目总览

助手从资料中填表，用户回顾并补充，不要求用户先填信号清单。模板先按 [内置模板及来源](templates.md) 查找，已有可用模板时不重复向用户索要。固定列为：

|类别|本项目实际配置|拟测试方法|其他|
|---|---|---|---|
|按实际功能分组|产品实际对象、数量、方向及必要结构|一句话说明建议测法|必要约束、缺项或待确认条件|

按本板实际电路生成行：芯片/板卡数量和职责、对外通信和输入输出、供电轨、AD采集、功率输出与负载。分类用于反查遗漏，不是固定测项表。不要仅按FCT结构体取项目；有实际功能但FCT缺回传时仍列候选。

- 方法写“工装集中检测”“采样协议对比”“静态温度对比”等简述，不在第一步铺报文、全部针点或MCU采集归属。没有“接口/采集归属”列。
- 主通信口优先选择真正对外的接口。2×5端子在本用户项目中通常内部使用，仍按电路核实；其他选择通信收发法的外置口拟用进入FCT验证，不默认分摊后续测试；电流环允许只做固定高低状态和真实RX回传。
- 芯片间内部通信不单列展示，依赖已有保护故障码；软件检查时仍核对相关机制。
- FG实际配置描述产品的正常输出功能及开漏/推挽结构；测试方法描述进入FCT后的固定脉冲。不能把固定产测脉冲写成产品常态。
- 同类且测法相同的信号尽量归一行；有不同条件时写清区别。其他列只留影响选择的事项，详细证据留工作记录。

表后集中列出影响方案的少量待确认问题。用户可增删检测项目；确认后进入第二步方案规划，不把总览当最终测试点表。

## 项目记录与交付状态

记录板号/版本、模板路径、已确认测项、负载/供电、当前步骤及尚未确认的关键条件即可。输入目录格式见 [输入资料规范](input-package.md)，不重复要求填写整套问卷。

分别记录：方案确认、正式资料完成、针点机械可达性、可选软件审核、编译、联调与量产验证。未开展项写未开展或未选择，不把文档完成等同于代码或实机通过。
