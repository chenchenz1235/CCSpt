# 测试范围与电路检测方法

按实际对象阅读相应章节；示例定值须由新项目验证。

## 2 FCT测什么 不默认增加什么

目标是检查基本装配和硬件通路，如错件、漏焊、虚焊、短路、采集及驱动异常。测试项目必须对应实际存在且需要验证的功能，不能因为旧模板有一行就保留，也不能声称有限的检测能覆盖所有器件故障。

|类别|默认考虑的基本检测|不默认追加的内容|
|---|---|---|
|供电与电源轨|规定供电下检测板上实际存在的电源轨及关键电压采集|全工作范围扫描、完整电源性能与温升测试|
|TTL、RS485等通信|各待测外置口依次发送进入FCT报文、逐口确认有效回复；全部通过后固定一个外置口完成剩余测试|仅读版本代替进入FCT确认、后续在多个口间分摊测试、虚构主从转发|
|开关量输入|外部端子施加高/低或开/合，回传真实输入|只回显工装命令；为内部输入额外加针|
|温度电阻输入|每路一个固定电阻，回传原始AD码|默认两档电阻、多点曲线或温控算法验证|
|IPM温度|静态温度经协议与环境温度比较|默认再扎温度输出电压点|
|电流零点|停止/PWM关闭的对应条件下回传各实际采样通道原始AD码|把重构相当作独立AD通道、带载精度标定|
|LED及辅助输出|LED点亮后测一次A-K压降；辅助输出检测分组高低状态|无明确需要的光学设备、复杂动作序列|
|电源继电器|按现有吸合逻辑进入检测状态，测规定驱动端|为测试而绕开原有时序、强制开关AC/DC电源继电器|
|电机驱动|按板型确认固定电机或指定电感负载，短时输出并检查电流检测结果与故障|带载输出能力、长期稳定性、温升等老化项目|
|VSP、PWM、FG等接口|存在时按方向和硬件形式设计实际采集与协议对比|只回显软件设定值就判定端口通过|
|专项保护|按真实电路、已确认需求决定|默认短路功率级、增加过流/过压等专项注入|

上述取舍用于本类工装的范围约定，不替代产品另行要求的ICT、耐压、安规、校准或老化项目。

没有硬件比较器锁存器时，不默认安排锁存专项和通信清锁存步骤。已经明确保留的可选故障输入检测，可以验证“输入信号到软件响应”，但不等于验证IPM过流全链路。有锁存器且确需专项时，依据实电路明确触发、撤除和复位方法；存在干扰误触发时按项目决定可不测，不借此默认关闭常规保护。

### 测试项目完整性检查

先沿实际硬件功能与信号路径提取候选项目，再查正常业务代码的数据生产者和执行者，最后对照FCT现状；供电轨、VAC/VDC、温度、电流、通信等分类仅用于反查遗漏，不能视为固定必测表；不能仅按FCT结构体字段提取项目。每项建立“硬件功能→检测方法→测试点或协议字段→流程阶段→判据”的对应关系。各项必须明确纳入、用户确认不测，或有具体原因的待定；缺少FCT字段/命令应列入第二步待确认差异，使用者决定测法或软件修改后再进入正式方案，不能默默漏项或自行定案。VAC/VDC的采样节点电压、原始AD和换算物理量分别说明，不混用判限。

### 多通信口的统一流程与多芯片判断

以下能力判断属于第二步，用于提出软件配合建议，不以旧FCT缺失限制目标范围。优先对外主口统一完成；确实缺少所需能力时，才提出驱动直连等例外，由用户确认，不把历史某板的直连选择当成通用前提。

本用户约定：以下逐口规则只适用于已选择通信收发法的接口；仅做高低状态检测的电流环除外。同一控制对象有多个支持进入FCT的待测外置口时，依次通过各口发送进入FCT报文，并从对应口确认命令匹配、校验及状态正确的回复；已进入FCT后继续从其他口重复进入，不在各口之间退出或断电。多次发送用于覆盖不同接口，不是同一个口无判据重发。超时或错误回复按通信失败处理，不继续功能测试。全部接口通过后，固定一个外置口完成后续测试，不在每个口重复整套功能测试。先核对重复进入不会清除结果或意外启动负载。

多芯片项目须按实际能力逐项判断，不能把“缺少进入FCT命令”概括成“驱动不支持FCT”：

1. 分别核对每颗芯片、每个待测口是否实现进入FCT、拖动启动、停止、状态读取及必要的其他命令，追踪到执行与回复。仅有命令宏定义或同名函数不算已实现。驱动缺少进入实现时，先判断能否在已有进入命令框架下补齐，列为第二步软件配合建议；确需用不启动负载的查询验证收发时，作为例外交用户确认，不自动替换统一进入方式。不能声称尚未实现的命令已可用。
2. 判断选定外置口能否覆盖驱动操作。主控需通过转发访问驱动时，核对目标地址、封装、长度、校验、请求下发、驱动执行、回复转回原请求口，以及超时处理；协议给出实际转发帧。能下发但不能返回，不算完整支持。主控已回传的真实驱动状态可按语义用于判定，但不能冒充某条命令的确认回复。
3. 若进入及后续所需命令均可通过保留外置口完整完成，后续统一使用该口；驱动命令需要转发时明确使用转发协议，不把驱动直连帧直接发给主控。
4. 先区分已有架构能补齐的实现与缺少协议能力。确实不能通过主口完成时，才建议保留驱动直连口执行必要的拖动启停、状态读取；其余测试集中主口。由用户确认直连或新增能力方案，不为追求单口而擅自改固件。确认后在流程、测试点和协议中一致标明通道。
5. 无论选择转发还是直连，都核对主控周期命令是否重新触发拖动，以及最终停止是否有效。不能把通信验证变成启动电机；缺少所需收发适配、执行或停止路径的项目仍单列差异，不声称已经通过。

## 3 每项检测都写成同一种结构

每项内容至少说清：前置状态、外部接法、工装激励、板上动作/实采、回传字段或直接测量、等待条件、通过判据、结束状态。

例如“电流零点检测”不应只填“读取电流正常”。应写成“电机停止且PWM关闭；通过既有读取命令获取主U/V和风机V/W原始AD码；按各通道判限分别判断；检测期间不得启用拖动”。

检测方式按最终判据区分：

|标注|判断依据|例子|
|---|---|---|
|测量|工装直接测得的电气量|LED两端压降、ULN输出端电压|
|协议对比|板子实采后回传的数据|Di电平、零点AD、IPM温度、PWM输入占空比|
|测量＋协议对比|两种结果都明确要求|工装测母线电压，同时核对板回传值|
|通讯收发验证|经被测接口成功往返匹配命令|TTL和RS485分别握手|

通过协议发控制命令，随后工装测电压，仍属于“测量”。不使用“捕获”等不能说明判断依据的模糊备注。

## 4 常用电路的检测方法

### 4.1 电流环通信

电流环可选择通信收发验证或固定高低状态验证，不强制两者都做。用户选择高低状态法后，不再要求经该口发送进入FCT报文；由主测试口控制并回传真实RX。先从原理图确认发送器件、接收器件、偏置/限流、回路参考端及隔离关系，再设计固定高低电平测试。名称同为电流环，并不代表都能采用相同电源和回路接法。

本次采用的流程是：按该板条件给COMM回路供电，MCU_TX置高，稳定后读取MCU_RX；再置低、稳定后读取。通过保留的TTL等接口回传RX，工装判断两个状态。备注为“协议对比”。预期是否同相要看实际反相级数，不能固定套用TX高必定RX高。

关键检查：GPIO与串口复用已正确切换；TX变量有执行到物理引脚的代码；RX来自输入寄存器；稳定时间考虑电路响应；退出或结束状态明确。正常测试不要求通过该电流环跑完整协议，也不默认加多轮切换。

回路电压、电流与限流电阻应按实际电路重新计算，并通过样板验证。

### 4.2 LED

团队基线是在输出组中稳定点亮后测一次A-K压降，备注为“测量”。可控LED允许在FCT控制点亮，常亮LED按正常供电测量；不使用光感设备。根据第一步实际对象决定安排在哪一组。

先明确到底测LED的A对K压降，还是电路中另一个器件的导通压降。A对GND不一定等于A对K，K也不一定是GND。工装若不能直接差分测量，需确认可实现的两点测量/差值方案；不能直接把K接地来迁就量程。

默认只测点亮一次，不增加熄灭检测或重复组测；用户明确要求其他状态时再分别设判限。数值依据器件、工作电流、接法及样板，不直接把0.7V写成所有LED的标准。此方法按所测电气通路判定，不自动等同于完整发光强度或光色检测。

### 4.3 电流零点

先查软件配置，再核对电路及实际采样通道，最后填写理论零点和工装范围：

1. 优先查本工程有效的matlab_variable.c及参数初始化，搜索current_zero_ad_offset、fan_current_zero_ad_offset，以及PFC/PV对应的pfc_i_offset_ad、mppt_i_offset_ad或等效参数。核对实际机型、编译分支、参数覆盖及使用位置；不能只找到同名变量就认定当前生效。
2. 区分配置的标称零点、启动时测得的校准偏置和实时原始AD。标称参数用于理论中心，不能把每块板自校准得到的偏置自动当成验收中心而掩盖装配偏差。
3. 核对ADC实际物理通道、偏置电路、参考源及零电流条件。电机常见2048 AD，但不能当作固定值；PFC、PV及其他输入电流分别查。两电阻采样系统的重构第三相不作为独立零点AD检测。
4. 理论值有有效程序参数和电路依据时直接填写，不因工装容差未确认而把理论也写成待确认。只有缺少依据或软硬件冲突时才列具体待确认项。
5. 分开记录理论零点、软件保护偏差阈值、工装验收上下限。current_ad_offset_diff_max、pfc_i_ad_offset_diff_max等是保护门槛，不自动转为产线判限，也不套电源轨容差（5V为±0.2V，其他轨默认±0.5V）或VSP±0.2V。工装范围沿用已确认标准或另行确认；同时核对边界比较符号。


填写示例：“理论：2048 AD；范围：待确认（工装允许偏差尚未指定）”，备注标出有效参数及来源。此处待确认仅指验收范围，不否定已查明的理论零点。

工装通过协议读取原始AD码；即使报文载体是float32，2048.0仍表示2048 AD，不是2048V或2.048A。回传使用独立观察字段，不覆盖电流控制或保护变量。

电机侧通常在停止、PWM关闭条件下读取；输入电流通道需考虑上电静态耗流，不能假定所有通道都恰好零电流。分别设定各电路零点，不能把电机偏置套到交流/光伏输入电流。

用于估算的关系：AD≈输入电压/参考电压×2^N，码值上限为2^N−1；最终按目标ADC的数据手册、对齐方式及现有缩放确认。以5V、12位为例，2.50V约2048 AD，1.49V约1221 AD。公式表达的是原始码与输入量程关系，不替代参考误差、分压误差、偏置误差及噪声评估。[TI关于ADC码值与电压换算的说明](https://e2e.ti.com/blogs_/archives/b/precisionhub/posts/it-s-in-the-math-how-to-convert-adc-code-to-a-voltage-part-1)

若旧判限给的是电压，可先做等效AD换算，再明确待样板确认。例如本项目2.4～2.6V对应连续码1966.08～2129.92，整数采样按包含关系取1967～2129。若回传的是平均后的非整数AD，需另行约定边界，不能机械使用整数取整规则。

### 4.4 温度电阻与IPM温度

外接温度电阻：每路从外部端子接一个已确认固定电阻，读取该路原始AD；不默认增加第二档或完整温度曲线。理论AD由实际分压方向、阻值、激励电源和参考源计算，不能看到20kΩ就认定一定是半量程。

IPM温度：沿用板上温度计算，回传℃，静态稳定后与环温对比，不默认增加内部温度电压扎针。环境温度来源需明确，用户默认允许偏差为±5℃，项目明确值优先。不能把“统一用AD”误扩展到所有电压、温度字段。

### 4.5 Di和触点输入

按电路选择端子开路/短接或合规的电平激励，读取真实输入电平。若多路可以交叉高低，优先避免全部同时为高导致通道互换难以识别。

短接到哪一脚由原理图决定；第二脚可能是电源而非地。不要仅凭连接器外观外灌5V，也不要按逻辑名称猜开路默认高低。

### 4.6 辅助输出及电源继电器

电子膨胀阀、四通阀、外接继电器等辅助输出，可用检测组统一导通/关闭，各路分别测量。默认不加电子阀步进算法或逐路one-hot动作。若确需增强通道间短路辨别，再作为额外覆盖需求设计，不声称两组测试已覆盖全部短路。

对ULN等下拉驱动，导通测输出对参考地的低电压，释放后通过实际负载/上拉回到负载电源。输出器件并不主动提供高电平，导通也不严格等于0V；有既有负载或工装通道已有合适上拉时不重复加上拉。可直接称为“带上拉测输出高低电平”；模拟负载可只是电阻，不要求真实阀或继电器。检查测试负载的电流和功耗与接口匹配。

AC/DC电源继电器与辅助输出分开处理：保留程序正常吸合、预充或互锁逻辑，给定供电并等待到位后检测，不为工装强行开关。本项目驱动端导通压降用于吸合驱动状态判断，但不能单凭它证明机械触点已闭合或接触电阻合格。如确需触点检测，另明确测量通路和工装能力。

### 4.7 两台电机

工装能力允许时一起启动、分别检查、一起停止，不无理由重复单独拖动风机。回传必须区分主电机与风机状态和故障。

工装等待检测窗口完成再判定；初始零值、命令确认、采集中状态不能当成通过。重复测试时清本轮累计值、峰值及计时，核对两路故障来源，防止上一轮好数据造成误判。停止命令的确认不代替实际停车确认。

## 5 VSP PWM占空比及FG接口怎么测

本节提供可复用设计方法，不表示当前项目已实现或已实测。

### 产线固定FG测试信号与拖动

本用户产线FG等输出通常采用FCT模式下产生的固定测试脉冲，用于检查输出通路，不是电机真实转速反馈。逐板核对实际触发条件：进入FCT立即生效，还是进入后还需选择输出组；按程序写操作，不一律把进入模式等同于脉冲已输出。检测规定频率、适用占空比及输出电平/上拉，不把频率换算成电机转速作为通过条件，不拿回传的占空比常量当实测。

产线“拖动”用于检查功率驱动及电流采样，按本板检测窗口、采样结果和故障判定；本用户不要求电机真实连续旋转，不以是否旋转、实际转速或FG速度反馈作默认通过条件。固定FG可以在无实际转动时测试。检查输出组是否联动启动拖动，避免将零点检测排到已通流之后。

### 5.1 先辨认接口形式和方向

VSP只是常见信号名，不能仅凭名称决定测试方式。它可能是模拟速度输入，也可能与PWM控制或PWM滤波输出相关。例如TI的一款参考设计将VSP明确用作模拟速度输入，说明必须看具体接口定义。[TI TIDA-01496设计说明](https://www.ti.com/lit/ug/tidudd8/tidudd8.pdf)

|实际电路|工装动作|板子回传什么|判定方法|
|---|---|---|---|
|模拟VSP输入|从外部端子施加已确认固定电压及参考端|该输入真实AD码|协议对比输入分压/采样链路|
|PWM或占空比输入|施加规定幅度、频率、有效极性、占空比的信号|实际捕获的占空比；需要时回频率/周期及有效状态|协议对比捕获结果|
|频率或FG输入|工装模拟规定脉冲源；按开漏/推挽形式接线|实际捕获频率或周期，必要时有效状态|协议对比；不强行解释成转速|
|VSP模拟输出，有实际AD回采|下发输出档位，接规定测试负载|输出经真实回采链路得到的AD值|协议对比，并说明回采点覆盖到哪里|
|PWM输出，有真实捕获回路|下发输出档位，按方案经端子回接可测输入|回接输入实际捕获的占空比/频率|协议对比，核对环回实际走过的电路|
|输出没有任何回采路径|由工装在输出端实际测量，或评估增加外部环回|没有可用实测回传就不造一个“反馈值”|按真实方式标“测量”；仅回显设定值不算协议验证|

如果模拟VSP经低通后的AD回采，验证的是该处模拟电平；不能用平均值宣称PWM频率和脉宽都正确。内部MCU引脚环回也不能证明外部端子、光耦或驱动器之后的链路完好。

### 5.2 模拟输入的实施步骤

1. 确认方向、允许电压、参考地、分压及输入保护，决定端子接法。
2. 在允许范围内选固定测试电平。基本装配检测可先采用单点；需要辨别卡死、反相或比例关系时再采用两个差异明显的点，不默认做全量程扫描。
3. 等待输入滤波和软件采样稳定，回传实测原始AD，不用速度命令或滤波前后不明的变量代替。
4. 按实际分压比例、ADC参考和误差设判限；撤除激励后的处理写入流程。

### 5.3 PWM或频率输入的实施步骤

1. 固定信号源频率、幅度、输出类型和参考端；开漏需要确认上拉由谁提供。若存在光耦反相，在协议里明确回传的是外部高电平占比还是内部有效电平占比。
2. 选择接口允许范围内、避开端点的占空比。仅作设计示例可考虑30%和60%两个点；实际点数、频率、幅度和限值由本板要求确定，不能将这些数字直接写为通用定值。50%单点不利于发现占空比反相。
3. 板子通过定时器实测高电平时间及周期，再计算占空比和频率并回传。通常D=t_high/T、f=1/T；计数值还需用实际定时器时基换算。ST的官方PWM输入示例同样用实际捕获值计算这两项。[ST AN4157第3.23节](https://www.st.com/resource/en/application_note/an4157-stm32f3discovery-peripheral-firmware-examples-stmicroelectronics.pdf)
4. 协议明确占空比是0～1、0～100%，还是带缩放整数；频率是Hz还是周期计数，并写清每项对应的捕获来源。
5. 在联调中确认断信号后不会无限保留上次有效数据；无新边沿、超时、0%/100%等不能测周期的情形有明确处理。这不等同于必须把所有边界都加入每块板的产线步骤。

典型填写方式：“工装向指定PWM输入端施加规定信号→等待稳定→读占空比/频率实采字段→与施加值及容差对比”；备注“协议对比”。单纯给软件变量赋值再原样回传，没有检测硬件端口。


## 负载选择与低压板案例

先确认本次是FCT还是老化，再确认板型、负载和测试电流；工装品牌、命令名“拖动”和电感负载本身不足以决定用途。不把固定电机0.5A或电感5A设为通用规则。

低压板可能需要专用小电感负载及不同于常规电机的测试电流；以项目确认的负载、固件设定和验证结果为准。

在接线配置写明负载类型、实际接法及测试电流命令，负载接点确需扎针时才列入测试点表；在流程写明适用负载，选择原因放配置说明或软件指导；在协议区分启停参数与固件电流设定。电感通流验证驱动输出和电流检测，不用电机是否旋转或转速作为判据，也不自动等同于老化验证。负载型号、电感量、额定电流及拓扑未提供时标为待记录，不能用任意电感替代。按实际程序重新核对采集窗口、峰值门槛、停止和复测条件；软件命令值、检测门槛和外部实测值分别表述。
