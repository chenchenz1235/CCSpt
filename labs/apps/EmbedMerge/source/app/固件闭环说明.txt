# Python 固件加密、Boot 更新与电机控制原型

从原有软件 AESHelper、MotUtil、BootLoaderCommHelperNew、CommHelper 移植协议。原 MFC 软件保留不动；Python 包为 `firmware_tool`。旧 C# 试做目录 `FirmwareTool` 不作为交付入口。

## 运行与集成

- 升级入口：`dist/Bootloader/Bootloader.exe`。
- 加密入口：`dist/DevMngRegister/DevMngRegister.exe`。
- 两个目录需连同 `_internal` 一起保留；无参数打开桌面界面，有参数使用 JSONL 命令行。
- Python 集成可安装本项目或直接导入包；导入本身不连接硬件。
- 依赖为 cryptography、pyserial；`build_python.ps1` 使用本地 .venv 和 PyInstaller 打包。
- 保留公司授权的进程名，文件访问权限以实测为准。日志不输出密钥。

```python
from firmware_tool import encrypt_file, Image, load_file, Bootloader, SerialLink, Settings
result = encrypt_file("project/DefaultBuild/only_app/app.mot", "output/app.em")
# Host may supply an explicit CryptoProfile rather than load the legacy source profile.
```

## 命令行

```powershell
.\dist\Bootloader\Bootloader.exe artifact --project '工程路径\工程.mtpj'
.\dist\DevMngRegister\DevMngRegister.exe inspect --file '工程路径\DefaultBuild\only_app\工程.mot'
.\dist\DevMngRegister\DevMngRegister.exe encrypt --file '工程路径\DefaultBuild\only_app\工程.mot' --out '新文件.em'
.\dist\Bootloader\Bootloader.exe inspect --file '新文件.em'
.\dist\Bootloader\Bootloader.exe simulate --file '新文件.em'
.\dist\Bootloader\Bootloader.exe discover
```

`discover` 枚举串口，从 9600/N 开始，发送原软件 F0/01 连接握手、F0/03 拓扑读取；App 不应答则查询只读 Boot 信息。默认候选波特率 9600、19200、38400、57600、115200、4800，校验 N/E/O，可显式指定列表。候选列表是本工具的扫描策略，不代表原软件会遍历全部组合。探测不进入 Boot、不擦除、不运行电机。

`flash` 必须提供 .em、串口、App/Boot 波特率、升级路径、产品 ID、文件 SHA-256。默认仅返回计划，加入 `--execute` 才操作硬件；可选 `--already-boot`。EmbedMerge 默认 Boot 9600/N，失败时以只读 Boot 信息查询确定 UART 配置。支持直连驱动、直连接口、经接口转发到驱动，一次更新一个目标。默认保留数据区；`--erase-data` 对应原软件四个 FF 擦除标记。

仅生成 .em，支持 bootloader_lite；遇到 bootloader_en 拒绝擦除。.etm 生成流程尚未建立，不能仅改扩展名。旧格式为固定配置 AES-256-CBC/PKCS7，为兼容保留，没有新增签名或鉴权能力。

`motor --action stop|speed|run` 复用 F4/05、F4/06+D1+小端 float32、F4/04，可选 `--forward` 添加 AB/01。默认仅出计划；设转速和运行需提供 rpm、max-rpm，运行还需 0–60 秒的明确时长。结束、取消或 START 应答丢失时尝试停止；串口断开时不能保证停机，应答不证明实际转速。

## CS+ 与 Boot 产物

`build --project 工程.mtpj` 输出计划；`--execute --log 日志.txt` 执行 `CubeSuite+.exe /br DefaultBuild /lang en-US 工程.mtpj`，检查退出码及 only_app 中唯一 MOT 的更新时间。命令行依据：[Renesas 官方文档](https://tool-support.renesas.com/autoupdate/support/onlinehelp/csp/V8.14.00/CS%2B.chm/po-ProjectOperation.chm/Output/po_function_command-nav-2.html)。

**只有 DefaultBuild/only_app 下的 MOT 用于 Boot 更新。** 不使用 DefaultBuild 根目录完整 MOT。构建时间检查阻止沿用未更新输出；编译成功不等于参数正确或实物验证通过。

## EmbedMerge 演示闭环

新增“固件与电机”面板，后台接入现有本机鉴权外部控制接口。手机到 PC/Codex 的连接沿用已有控制方式；本次不开放公网服务。

运行 `start_demo.ps1` 可打开已打包的 EmbedMerge，并使用独立 `demo-data` 进入原生单页参数审核，加载错误工程的参数文件；审核结论需由技能实际运行生成，不能用左右差异代替。原始基准在 `example/driver/project`，注入版在 `example/demo-driver/project`：`speed_min` 从 300 改为 2500，`speed_max` 保持 2400。可在代码高亮处点击展开问题详情、编辑拟修订，保存时选择写回原文件或仅保存副本；写回前自动备份并检测外部冲突。

此演示通过外部比较的 `forBuild:true` 选项保留编译所需的二进制输入（例如工程原有 bootloader BIN），避免普通比较过滤器漏复制依赖。其他普通比较默认规则不变。

1. 用“打开工程审核”或 AI 的 review-project 入口加载工程，默认单页显示参数代码；复用 ccspt-code-review，定位高亮问题，点击展开详情，编辑后保存并可写回原文件。
2. 项目资料可选：不提供时直接按默认规则检测；可选择任意文件或工程目录，不以文件扩展名或立项关键字阻止审核。无法提取资料时记录限制并继续默认规则，仅对依赖缺失依据的条目标注待核实。
3. 当前 TEST 工作副本选择 mtpj，查看计划，再执行 CS+ 编译。
4. 查找 only_app MOT，检查、加密为任务产物目录下的新 .em，记录路径和哈希。
5. 探测设备，核对连接、ID 和文件哈希，查看升级计划后执行。擦除前检查版本、ID、全部数据地址范围；CRC 通过后才设置有效标志。
6. 使用已确认的 App 串口参数，填写演示转速、上限和时长，运行并定时停止。

```javascript
import {callEmbedMerge} from 'F:/SVN_vscode_project/EmbedMerge/app/core/external-client.mjs';
```

操作为后台任务，状态可查询、事件同步界面、完整 JSONL 日志写入任务 artifacts/firmware。取消通过协作文件传递，不强制杀死刷写或运行电机的进程；CS+ 构建需等待原生进程结束。

## 验证边界

测试覆盖 S1/S2/S3、错误校验与重叠、AES 已知向量、文件往返、分片串口应答、写入 CRC、范围/ID/版本失败时禁止擦除、CRC 失败时禁止有效标志、旧/新握手、转发升级、取消、START 应答丢失后的停止尝试。

提供的 only_app MOT 与原 .em 明文哈希不同，不能当作配对文件。新生成 artifacts/example-python.em 与当前 MOT 的明文 SHA-256 一致，模拟升级通过。真实编译、板卡更新、电机运行及完整手机语音演示以最终验证记录为准；模拟结果不代表实物通过。

固件初版验证：Python 19 项通过；EmbedMerge 当时98项通过、1项因文件系统不支持硬链接而跳过；独立窗口验证加密与模拟升级通过。未注入错误的基准副本已由真实 CS+ 重建成功（0 错误、15 警告），only_app MOT 更新后加密及模拟升级通过。没有枚举到串口，未刷写真实板卡或运行电机。详见 `artifacts/verification.json`、`artifacts/compile-check/csplus.log` 和 `artifacts/demo-speed-review.html`。
